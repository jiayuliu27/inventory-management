Data Flow — Filtered Dashboard Request

  1. User changes a filter (Time Period, Warehouse, Category, or Order Status) in the FilterBar. client/src/components/FilterBar.vue
  2. Shared filter state updates. The refs live at module scope in the composable, so every view sees the same singleton state — no Vuex/Pinia needed. client/src/composables/useFilters.js
  3. Views react and call the API client, which builds query params, skipping any filter set to 'all'. client/src/api.js → GET /api/dashboard/summary?warehouse=…&month=…
  4. FastAPI filters in-memory lists. apply_filters() matches warehouse/category/status; filter_by_month() matches a month directly or expands a quarter like Q1-2025 into its three months. server/main.py
  5. Pydantic validates the response against the declared response_model and FastAPI serializes it to JSON. server/main.py — model classes
  6. Computed properties derive display data — metrics, tables, and custom SVG charts re-render automatically from the updated refs. client/src/views/*.vue

API Surface

  • GET /api/inventory, /api/inventory/{id}Filters: warehouse, category (no time dimension)
  • GET /api/orders, /api/orders/{id}Filters: warehouse, category, status, month/quarter
  • GET /api/dashboard/summaryAll four filters; key metrics for the dashboard
  • GET /api/demand, /api/backlogForecasts and delayed items; no filters
  • GET /api/spending/summary | monthly | categories | transactionsSpending analytics endpoints
  • GET /api/reports/quarterly, /api/reports/monthly-trendsAggregated reporting data
  • GET /docsInteractive Swagger UI (auto-generated)
Known gap client/src/api.js defines calls for /api/tasks (GET/POST/PATCH/DELETE) and /api/purchase-orders (POST/GET), used by TasksModal and the backlog purchase-order flow — but server/main.py implements none of them. Those UI features will receive 404s until the backend routes are added (purchase-order data and Pydantic models already exist server-side).

Demo Constraints

  • In-memory data only — mutations don't persist; restarting the backend reloads the JSON files.server/mock_data.py
  • No authentication — useAuth serves a hardcoded mock user profile.client/src/composables/useAuth.js
  • CORS allows all origins (allow_origins=["*"]) — development convenience, not production-safe.server/main.py
  • Internationalization included — English and Japanese locales via a lightweight custom composable.client/src/composables/useI18n.js, client/src/locales/
